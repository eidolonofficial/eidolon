# Decision log: 2026-06-08 v1 canary run

Append-only. This entry records the first end-to-end run of the spec-driven
build pipeline against the eidolon repo itself (design spec section 21 "v1 is
done when", and build path item 4).

## Context

All five v1 components were built and shipped (commit bd23af0). This run is the
acceptance test: drive a small real change through SPECIFY -> PLAN -> BUILD ->
REVIEW -> VERIFY -> FIX -> CLOSE and confirm the spine catches a seeded defect,
bounds the fix loop, and closes with a record.

## The work item

A genuine deliverable: `scripts/selfcheck.mjs`, which verifies eidolon's own
invariants (every hook parses, settings.json is valid JSON, the skill and
reference and hook docs carry no em or en dash). This is the recursive
verification antibehavior defense (section 10) made runnable. Spec:
`docs/spec/2026-06-08-selfcheck-canary.md`. Tier: standard (a new executable
surface that shells out, so the security swarm ran).

## Findings and disposition

| # | Stage | Finding | file:line | Disposition |
|---|---|---|---|---|
| 1 | REVIEW (red) | Seeded CWE-22 path traversal: `--profile` name joined into `profiles/` unsanitized | selfcheck.mjs:54 | Fixed: bare-name guard plus `inside()` confinement to profiles/ |
| 2 | REVIEW (red) | Unconfined `extra.files[]` from a profile read arbitrary paths (CWE-73) | selfcheck.mjs:56 | Fixed: each listed path confined to the repo root |
| 3 | REVIEW (red) | Unguarded `JSON.parse` on the profile (CWE-248) | selfcheck.mjs:55 | Fixed: wrapped in try/catch with a graceful fail |
| 4 | REVIEW (red) | `--dir` as attacker-controlled base | selfcheck.mjs:19 | Accepted: documented by-design feature, LOW, no standalone attack |
| 5 | VERIFY (cold) | Source contained literal U+2014 / U+2013 in the dash regex, violating the ASCII code style the script itself enforces | selfcheck.mjs:44 | Fixed: replaced with `—–` escapes; detection semantics preserved |

## How the spine behaved (the proof)

- The security red swarm ran cold (only the file plus the methodology) and caught
  the seeded CWE-22 at the right file:line (selfcheck.mjs:54), plus two genuine
  adjacent findings, and correctly cleared `execFileSync` as not a vulnerability.
- Blue hardened all three; post-fix verify ran on an independent signal (dynamic
  invocation) and confirmed traversal is refused without reading the target file,
  while the legitimate in-repo profile still works.
- The cold-context verifier (only the diff, the spec, and the rubric) re-derived
  the verdict and caught a fault the build and the security pass both missed: the
  literal dash at selfcheck.mjs:44. This is the second-signal architecture working
  as designed: a verifier that cannot inherit the build's reasoning saw what the
  build was blind to.
- The fix loop ran one iteration (VERIFY red -> FIX -> re-VERIFY PASS) and closed
  well under its bound of three.
- A real machine-level security hook also blocked the original `execSync` draft at
  Write time, a live demonstration of defense in depth at the earliest gate.

## Outcome

VERDICT: PASS on the re-verify across all five rubric items (security, functional,
encoding, parse, spec conformance), byte-level confirmed. The v1 spine is proven
end-to-end. Explain Mode answered a plain-language "what does this mean" about the
traversal with an explanation grounded in CWE-22 and offered a comprehension check.

## Decision

v1 is accepted. The committed `scripts/selfcheck.mjs` is the hardened version; the
seeded defect lived only in the working tree and never reached a commit, per the
only-CLOSE-commits rule. Next: layer v2 (the remaining swarms, the base persona
roster, expert hiring) onto a spine that now runs.
